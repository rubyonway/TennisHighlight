# 数据与统一报告约定

这是本 skill 辅助脚本的轻量数据约定，不要求把用户已有标注系统迁移成固定数据库。已有结构可保留，必要时生成临时适配 JSON。

## 逐球数据

`summarize_events.py` 接收一个 JSON 对象：

```json
{
  "scope": "两段原片全时段检查；只统计目标球员接来球，不含主动喂球。",
  "events": [
    {
      "id": "source-a-0001",
      "source": "source-a",
      "source_t": 12.4,
      "stroke": "正手",
      "result": "R",
      "result_evidence": "对方随后继续击球，未逐线确认界内。"
    },
    {
      "id": "source-a-0002",
      "source": "source-a",
      "source_t": 16.2,
      "stroke": "类型不明",
      "result": "U",
      "result_evidence": "目标球员出画，后续结果证据不足。"
    }
  ]
}
```

- `scope`：非空文本，说明范围、排除项及覆盖缺口。脚本不会把一句“全片”声明当作完成全片复核的证明。
- `id`：全包唯一，重试或重新识别不能让同一次回球重复累计。
- `source`：非空字符串或整数原片 ID；`source_t`：原片秒数，有限且非负。
- `stroke`：`正手`、`反手`、`类型不明`。不能把类型未知的球删除或塞进正手。
- `result`：`R` 估计有效、`N` 下网、`E` 其他未有效回出、`U` 结果不明。
- `result_evidence`：非空文本，说明依据或未知原因，不只写结论。
- 其他原有字段保留在输入文件；脚本不改输入，也不传播未经校验的旧汇总。

脚本仅接受用于汇总的本人回球记录。请先排除喂球、对手触球、空挥及重复候选，原始候选可以另存。若已有标注体系区分界内／界外，保留原标签，不要丢失证据以迎合此简化格式。

## 汇总口径

设 `total = R + N + E + U`，`known = R + N + E`。

- 可判结果内有效率：`R / known`；`known == 0` 时为 `null`。
- 结果覆盖率：`known / total`；`total == 0` 时为 `null`。
- 全样本未知极端范围：`[R / total, (R + U) / total]`，仅为算术范围，不是置信区间，也不覆盖漏检误差。
- 不同击球类型的比较要展示各自分母和未知量，不从高光样本推全场。
- 确认是回合延续的数据，报告名称用“估计有效率”或“回合延续表现”，不叫精确界内率、比赛得分率。

脚本输出 `scope`、`event_count`、`source_counts` 和 `summary`，其中 `summary` 包含三类击球及全部汇总。不会自动计算球速、挥拍速度、移动距离或落点。

## 高光时间轴与落点

每个片段保留独立原片和输出映射：

```json
{
  "id": "rally-a",
  "source": "source-a",
  "source_start": 10.0,
  "source_end": 25.0,
  "output_start": 0.0,
  "playback_rate": 1.0
}
```

正常速率下，`output_t = output_start + source_t - source_start`。均匀变速时除以 `playback_rate`；渐变速需要实际编辑时间映射。跨片段淡化用最终 `output_start`，而非未扣转场的长度之和。

落点记录包含 `id`、`source`、`source_t`、`clip_id`、`output_t`、`kind`、`xy_m`、`evidence_type`、`evidence`。缺失落点 `xy_m: null`。有先验则补充 `prior` 的来源、原话或准确摘要、适用范围、拟合方法；记录修订前坐标和时间。

坐标原点、方向、单位和单／双打边线必须写清。普通双打球场可用横向 10.97 米、纵向 23.77 米作为图示坐标，单打边线另画；目标机位和球场不匹配时重新校准，不直接套旧投影矩阵。

## 报告信息结构

以一个 `index.html` 或清晰命名 HTML 作为入口，按内容选取：

1. 概览：训练日期、对象、素材范围、最有依据的结论与下一次重点。
2. 视频复盘：集锦与各原片／浏览版选择、章节、倍速、音轨说明。
3. 技术统计：有分母的对比、未知数量、分素材结果；低可信度辅助估计折叠展示。
4. 落点：图例、证据级别、点击回放、缺失数量，注明高光或全片范围。
5. 动作建议：每项附证据时间／图片、观察、提醒、练法。
6. 逐球明细：原片、类型、结果筛选与分页；空结果可读；点击时间定位到击球前几秒。
7. 数据口径与数据下载。

同一指标的数字应从同一份数据生成，不分别手写在概览、图表、正文。没有数据的章节可省略，不能用历史项目数字填充。

## 播放器实现要点

- `controls`、`playsinline`、`preload="metadata"`；大文件旁放图片 poster。
- 切换视频后等待 `loadedmetadata` 再设置 `currentTime`，再尝试 `play()`；捕获拒绝并提示手动播放。
- 只让当前视频播放；不要同时运行多个隐藏播放器。
- 原片跳转使用原片时间，集锦落点跳转使用输出时间。可用两个不同按钮避免混淆。
- 内联 JSON 用 `json.dumps`，转义 `</` 或 `<`，避免用户文本截断 script；渲染普通文本使用 `textContent` 或 HTML 转义。
- 筛选变化回到第一页，筛选后总数和行数一致；未知类别不能从筛选选项消失。
- 原生键盘可用，图表点位有可访问标签。目录在桌面固定，窄窗口可横向或折叠，但保留可见的入口。
- 图片预留宽高或宽高比，避免懒加载后把锚点跳转的位置推走。复用模板时检查原有响应式 CSS 是否意外隐藏目录。

## 目录、媒体和发布

推荐一个交付文件夹：HTML 入口、`media/`、必要的可下载 JSON。工作脚本、临时帧、旧版本放项目的工作或归档位置。

本地媒体采用相对路径，媒体应是交付包中的真实文件，不能只是指向外接盘的符号链接。复制或同盘硬链接均可，修改硬链接文件会同时改动原文件，应把复用媒体视为只读。需要压缩或改字幕时写新文件。

有获授权的稳定远程媒体 URL 时可以使用，确认可访问性和签名有效期。制作 HTML 不包含默认发布授权。上传 skill 到 Git 时只提交可复用说明、脚本和人工合成示例，不夹带用户视频、私人逐球数据、凭据或个人路径。

## 验证范围

- 输入汇总检查能发现重复 ID、无效标签、空依据、负数／非数时间，不证明视频标签本身正确。
- 本地服务 Range 请求应得到 `206`、正确 `Content-Range` 和字节数。再在浏览器播放、拖动进度、跨视频跳转，确认时间实际推进。
- 检查至少一个章节、一个原片逐球时间、一个落点、筛选与清空、末页、窄窗口；按本次功能选择，不增加无关流程。
- 解码检查通过与网页可播放是两项不同事实。原片离线时明确使用缓存，并核对缓存是否全时长、有无声音。
